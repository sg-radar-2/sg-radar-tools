# 행동 분류기 (초안)

트랙 CSV를 읽어서 사람마다 **접근(APPROACH) / 이탈(LEAVE) / 체류(DWELL) / 배회(LOITER)**를 판정하고, 행동이 시작되고 끝날 때 JSON 이벤트를 만듭니다. 규칙 기반이라 판정 기준이 전부 `Config`에 숫자로 나와 있고, 녹화를 보면서 이 숫자를 조정해 나가는 방식입니다.

```
.pcr ──(tools/pcr/to_numpy_gui.pyw)──▶ <이름>_tracks_raw.csv ──(classify_csv.py)──▶ <이름>_events.json
                                                                                 └▶ <이름>_labels.csv
```

## 파일

| 파일 | 하는 일 |
|---|---|
| `behavior_classifier.py` | 분류기 본체. 프레임을 하나씩 넣으면 이벤트를 돌려주는 구조라 실시간에도 그대로 씁니다 |
| `classify_csv.py` | CSV를 프레임 순서대로 분류기에 넣어서 결과를 파일로 저장 (검증용) |
| `test_behavior_classifier.py` | 인공 궤적(직선 접근, 옆으로 지나가기, 서 있기, 원 돌기, ID 바뀜)으로 기본 동작 확인 |

필요한 건 Python 3.9 이상뿐입니다 (외부 패키지 없음).

## 실행

```bat
cd sg-radar-tools

:: 1) .pcr을 CSV로: tools\pcr\to_numpy_gui.pyw 실행 → "트랙 CSV도 저장" 켜고 변환

:: 2) 분류
python tools\behavior\classify_csv.py recordings\20261104_back_forth_walk_run_tracks_raw.csv
python tools\behavior\classify_csv.py recordings\*_tracks_raw.csv --out-dir results

:: 기준값을 바꿔서 돌려보기
python tools\behavior\classify_csv.py --dump-config my_config.json
:: (my_config.json을 고친 뒤)
python tools\behavior\classify_csv.py recordings\a_tracks_raw.csv --config my_config.json

:: 테스트
python tools\behavior\test_behavior_classifier.py
```

실행하면 화면에 이벤트 요약이 나오고, CSV 옆에 두 파일이 생깁니다.

- `<이름>_events.json`: 서버로 보낼 이벤트 목록. 행동마다 `phase: "start"`와 `phase: "end"`가 같은 `event_id`로 한 쌍씩 나옵니다.
- `<이름>_labels.csv`: 입력 행마다 평활화된 위치, 문까지 거리, 그 순간의 판정(`motion`), 진행 중인 행동, 계산에 쓴 값(속도, 방향 비율, 경로 길이 등). 판정이 이상할 때 이 파일을 열어 어느 값 때문인지 확인하면 됩니다.

```json
{"event_id": "Session #0-T0-APPROACH-3", "type": "APPROACH", "phase": "end",
 "session": "Session #0", "track_id": 0, "target_ids": [9], "time_s": 13.7,
 "x": -0.1, "y": 0.75, "distance_m": 0.76, "start_s": 9.2, "end_s": 13.7, "duration_s": 4.5,
 "start_distance_m": 3.33, "end_distance_m": 0.76, "reason": "motion_changed"}
```

## 판정 방법

좌표는 레이더 기준(x 좌우, y 정면)이고, **"거리"는 문까지의 거리**입니다. 지금은 레이더가 문에 붙어 있다고 보고 문 위치를 (0, 0)으로 두었습니다. 설치 위치가 정해지면 `door_x`, `door_y`를 바꾸세요.

1. **입력 거르기**: 포인트가 30개 미만인 관측은 위치를 믿기 어려워서 버립니다. 트래킹을 놓쳤을 때 마지막 위치에 멈춰 있는 값이 여기서 걸러집니다.
2. **트랙 잇기**: 사람이 사라진 지 4초 안에, 마지막 위치에서 1.5m 안에 새 레이더 ID가 나타나면 같은 사람으로 이어 붙입니다.
3. **짧은 판정**: 최근 1초 위치로 속도를 구해서 네 가지 중 하나로 정합니다. 0.5초 이상 유지돼야 확정합니다.
   - `still`: 속력 0.3 m/s 미만
   - `approaching` / `receding`: 문 쪽 속도가 0.3 m/s 이상이고, 움직임의 85% 이상이 문 방향일 때. 도플러가 같은 방향을 가리키면 0.15 m/s로도 인정
   - `moving`: 그 밖의 움직임 (옆으로 지나가기 등)
4. **행동 판정**

| 행동 | 조건 (기본값) |
|---|---|
| APPROACH | `approaching`이 이어지는 동안 거리가 0.4m 이상 줄면 시작, `approaching`이 끝나면 종료 |
| LEAVE | `receding`이 이어지는 동안 거리가 0.4m 이상 늘면 시작 |
| DWELL | 문 앞 1.5m 안에서, 3초 동안 순이동이 0.5m 미만인 상태가 10초 이상 이어짐 |
| LOITER | 최근 30초 중 80% 이상 3.5m 안에 있었고, 절반 이상 움직였고, 경로가 10m 이상인데, 직진도 0.35 이하이거나 접근↔이탈을 2번 이상 반복. 배회 중에는 접근/이탈 이벤트를 따로 내지 않음 |

숫자는 전부 `behavior_classifier.py`의 `Config`에 설명과 함께 있습니다.

## 지금 녹화로 확인한 결과

| 녹화 | 기대 | 결과 |
|---|---|---|
| 앞뒤 걷기/뛰기 | 접근·이탈 반복 | 접근 5, 이탈 5 (거리 변화 예: 3.33 → 0.76m 접근) |
| 좌우 걷기/뛰기 | 이벤트 없음 (지나가기) | 없음 |
| 둥글게 걷기 (54초) | 배회 | 처음 30초는 접근/이탈 반복, 30초 지점부터 배회 |
| sample-dataset 12 (3m 앞에 서서 팔 동작) | 이벤트 없음 | 없음 |

옆으로 지나가기와 앞뒤 걷기를 구분하는 기준(`min_radial_ratio`, `approach_min_dr_m`)은 이 녹화들로 맞춘 값입니다. 녹화가 네 개뿐이라 앞으로 바뀔 수 있습니다.

## 아직 정해야 하거나 부족한 것

- **문 위치와 문 앞 구역 크기**: 레이더 설치 위치가 정해지면 `door_x/door_y`, `zone_radius_m`, `watch_radius_m`부터 맞춰야 합니다.
- **체류·배회 녹화가 없음**: 문 앞에 10초 이상 서 있다 가기, 1분 이상 서성이기를 녹화해서 확인해야 합니다. 녹화할 때 정답 구간(몇 초부터 몇 초까지 무슨 행동)을 같이 적어두면 정확도와 오탐·미탐을 셀 수 있습니다.
- **배회 판정에 30초가 걸림**: 그 전까지는 접근/이탈로 보입니다. 더 빨리 잡고 싶으면 `loiter_window_s`를 줄이되, 오탐이 늘어나는지 같이 봐야 합니다.
- **문 바로 앞(1m 이내)을 옆으로 지나가기**: 거리 변화가 대부분 문 방향이라 접근으로 보일 수 있습니다. 녹화로 확인이 필요합니다.
- **여러 사람**: 한 사람 녹화로만 확인했습니다. 두 사람이 가까이 있으면 트랙 잇기가 엉킬 수 있습니다.

## 실시간으로 쓸 때 (라즈베리파이 / 서버)

CSV 대신 레이더에서 받은 프레임을 바로 넣으면 됩니다. `update()`가 돌려주는 이벤트를 그대로 JSON으로 보내면 됩니다.

```python
from behavior_classifier import BehaviorClassifier, Config, TargetObs
import requests

clf = BehaviorClassifier(Config(), session="door-1")

def on_frame(t, targets):          # 레이더 프레임 콜백 (t: 초)
    obs = [TargetObs(tg.target_id, tg.x, tg.y, n_points=tg.n_points, doppler=tg.doppler_mean)
           for tg in targets]
    for event in clf.update(t, obs):
        requests.post("http://SERVER/events", json=event, timeout=2)
```

# 문 앞 상황 판정 뷰어 (결정 트리)

접근·이탈 같은 동작을 넘어서 **문 앞에서 무슨 상황인지**(통과, 귀가, 외출, 방문/배달, 장시간 체류, 배회, 반복 접근, 도어락 조작 시도)를 결정 트리로 판정하고, 이상 상황이면 **카메라 촬영** 이벤트를 내는 과정을 화면으로 보여줍니다.

```bat
pip install numpy matplotlib scikit-learn
:: situation_viewer.pyw 더블클릭  (처음 한 번은 결정 트리 학습에 10초 정도)
```

| 파일 | 하는 일 |
|---|---|
| `scenario_sim.py` | 8가지 상황 + '멀리 서 있기'(해당 없음)의 가짜 궤적을 만들고, 레이더처럼 흔들림·격자·끊김을 넣어 `tracks_raw.csv` 형식으로 저장 (`python scenario_sim.py`) |
| `situation_core.py` | 특징 계산, 결정 트리 두 개 학습·저장(`models/`), 판정, 카메라 촬영 이벤트 |
| `situation_viewer.pyw` | 재생 화면 |

**결정 트리 두 개**

1. 움직임 트리 (프레임마다): 속력, 문 쪽 속도, 문 방향 비율, 도플러 → 다가옴 / 멀어짐 / 지나감 / 정지
2. 상황 트리 (0.5초마다, 지금까지의 흐름): 처음 잡힌 거리, 가장 가까웠던 거리, 연속 정지 시간, 문 바로 앞 정지 시간, 정지 중 손 움직임(doppler_std), 접근·이탈 횟수, 경로 길이, 직진도, 옆으로 이동한 비율, 앉음 비율, 사라졌는지 → 8가지 상황 또는 '판단 중'

상황 트리가 이상 상황(장시간 체류, 배회, 반복 접근, 도어락 조작 시도)을 60% 이상 확률로 1초 넘게 유지하면 촬영합니다.

**화면**

- 재생: 위에서 본 궤적과 문 앞 구역, 오른쪽에 6가지 관찰값 · 상황 판정 · **판정 근거(트리가 지나온 질문)**, 아래에 판정/정답 타임라인과 촬영 시점(▼)
- 시나리오 결과: 세션마다 정답과 최종 판정, 촬영 여부를 표로 비교
- 결정 트리: 두 트리 전체(글자 형태)와 검증 정확도, 혼동 행렬

**알아둘 점**

- 지금 결정 트리는 **가짜 데이터로 학습**했습니다. 흔들림 크기는 실제 서 있는 녹화(sample-dataset)의 속도 분포에 맞췄지만, 실제 성능은 정답을 붙인 녹화로 다시 학습·검증해야 합니다. '시나리오 결과'의 정확도도 같은 생성기로 만든 데이터라 실제보다 높게 나옵니다.
- 실제 녹화 4개에 돌려본 결과: 앞뒤 걷기 → 반복 접근(촬영), 둥글게 걷기 → 배회(촬영), 3m 앞에 서 있기 → 판단 중, 좌우 걷기 → 대부분 통과·판단 중이지만 마지막 사람(문 앞 1m를 19초 동안 세 번 왕복)은 반복 접근 → 배회로 촬영됨. 이런 경우를 이상으로 볼지는 팀에서 정해야 합니다.
- 트랙은 레이더 ID 그대로 씁니다 (behavior_classifier.py의 ID 이어 붙이기는 아직 안 들어감).
- 녹화에 정답을 붙이면 `scenario_sim.training_episodes()` 대신 그 녹화로 `situation_core.train()`을 돌리면 됩니다.

## 실제 녹화로 학습하기 (`train_situation.py`)

1. **녹화**: 시도 하나를 세션 하나(또는 파일 하나)로 찍습니다. 실수로 앞 내용이 누적됐다면 `tools/pcr/split_cumulative.py`로 먼저 나눕니다.
2. **정답 표** `recordings/labels.csv` (UTF-8). 파일 경로는 정답 표가 있는 폴더 기준입니다.

   ```
   file,situation,split,decide_s,target_id,session
   split/1-1.pcr,통과,train,2,,
   split/1-5.pcr,통과,test,2,,
   split/2-1.pcr,배회,train,10,,
   split/2-3.pcr,배회,test,10,,
   ```

   | 열 | 뜻 |
   |---|---|
   | file | `.pcr` 또는 `_tracks_raw.csv` (pcr을 바로 넣어도 됨) |
   | situation | 통과 / 귀가 / 외출 / 방문/배달 / 장시간 체류 / 배회 / 반복 접근 / 도어락 조작 시도 / 판단 중 |
   | split | `train` 학습에 사용, `test` 판정만 해보기 |
   | decide_s | 트랙이 잡힌 뒤 몇 초부터 그 상황이라고 말할 수 있는지. 그 전은 '판단 중'으로 학습. 비우면 처음부터 |
   | target_id | 그 행동을 한 사람의 레이더 ID. 여러 개면 공백으로 구분(예: `3 7`). 비우면 측정 영역 안의 트랙 전부. 한 파일에 상황이 다른 사람이 여럿이면 같은 파일을 여러 줄로 쓰고 줄마다 ID·상황을 다르게 |
   | session | 파일 안 세션 이름. 비우면 전부 |

3. **학습**

   ```bat
   python tools\behavior\train_situation.py recordings\labels.csv
   ```

   학습에 쓴 트랙과 뺀 트랙, test 녹화의 판정 결과(트랙별 최종 판정, 촬영 여부), 학습된 트리가 출력되고 모델이 `tools/behavior/models/situation_trees_real.pkl`에 저장됩니다. 옵션: `--with-sim`(가짜 데이터 섞기), `--depth`(상황 트리, 기본 7), `--final-depth`(최종 판정 트리, 기본 5), `--min-leaf`(기본 5), `--max-r`, `--out`.

4. **확인**: `situation_viewer.pyw` → **모델 열기...** → `situation_trees_real.pkl` → **CSV/PCR 열기...** 로 test 녹화를 재생합니다.

움직임 트리(다가옴/멀어짐/지나감/정지)는 가짜 데이터로 학습한 것을 그대로 쓰고, 상황 트리만 실제 녹화로 다시 학습합니다. 판정할 때도 한 번도 5m 안에 들어오지 않은 트랙(멀리 있는 벽·물체)은 판정하지 않습니다.

### 화면으로 학습하기 (`train_situation_gui.pyw`)

`train_situation_gui.pyw`를 더블클릭하면 같은 학습을 화면에서 할 수 있습니다.

1. **정답 표 CSV**를 고르면 '정답 표' 탭에 내용이 나오고, 같은 폴더에 .pcr이 없는 줄은 빨간색으로 표시됩니다.
2. **모델 이름**을 정합니다 (`tools/behavior/models/<이름>.pkl`로 저장, 같은 이름이 있으면 덮어쓸지 물어봄).
3. 상황 트리 깊이, 최종 판정 트리 깊이, 잎 최소 샘플, 가짜 데이터 섞기를 정하고 **학습 시작**. 결과 탭의 **틀린 것만**으로 틀린 트랙과 근거를 보고, 줄을 더블클릭하면 그 녹화를 뷰어로 엽니다. 정답이 상황 정의와 안 맞는 트랙은 **확인 필요** 탭에 나옵니다.
4. '진행 기록'에 쓴 트랙·뺀 트랙이, '결과'에 test(또는 train) 녹화의 트랙별 판정과 촬영 판단이, '결정 트리'에 학습된 트리가 나옵니다.
5. **뷰어에서 보기**를 누르면 방금 만든 모델로 test 녹화 전부를 `situation_viewer.pyw`에서 엽니다 (◀ ▶로 넘겨보기).

### 최종 판정과 녹화 판정 (우선순위)

한 사람에게도, 한 녹화에도 여러 행동이 나올 수 있어서 최종 판정은 아래 순서로 고릅니다 (`situation_core.predict`, `recording_verdict`).

1. 후보 모으기
   - 진행 중 판정(상황 트리)에서 60% 이상으로 1초 넘게 이어진 행동들 (그중 최고 확률)
   - 사람이 사라진(또는 녹화가 끝난) 순간 최종 판정 트리의 판정 = **끝날 때 판정**
   - 정상 행동은 끝날 때 정의 조건을 지키는 것만 후보 (예: 문으로 사라진 사람에게 진행 중 배달이 나왔어도 후보에서 뺌)
2. **이상 행동(장시간 체류, 배회, 반복 접근, 도어락 조작 시도)이 1순위**, 없으면 정상 행동
3. 같은 순위 안에서는 확률이 높은 것. 확률이 같으면 끝날 때 판정과 같은 것, 그다음 오래 이어진 것
   - 예외(`PRIORITY_OVERRIDES`): 한 사람에게 **외출**이 후보로 있으면 **장시간 체류**는 후보에서 뺌 (집에서 나와 엘리베이터를 기다릴 수 있음). 외출 후보는 문에서 나옴 등 외출 정의 조건을 지켜야 생김. 녹화 판정(여러 사람)에는 적용하지 않음
4. **녹화 판정**: 그 녹화(세션) 사람들의 최종 판정 중 같은 우선순위로 하나

학습 결과·뷰어의 결과 표에 '녹화 판정', '나온 행동(이상 먼저)', '끝날 때 판정'이 같이 나옵니다. labels_1111.csv 5겹 교차 검증: 녹화 판정 61/75(81%), 사람별 최종 판정 63/77(82%) (사라진 순간 판정만 쓸 때 77%/78%).

### 교차 검증 (k겹)

test 녹화 몇 개로만 보면 어떤 녹화를 test로 골랐느냐에 따라 결과가 크게 달라져서, 모든 녹화를 한 번씩 test로 써 보는 방법입니다.

- 정답 표의 `split` 열은 무시하고, 녹화 파일 단위로 k묶음으로 나눕니다 (같은 녹화가 학습과 test에 같이 들어가지 않음). 상황마다 골고루 섞이도록 상황별로 섞어서 돌아가며 나눔 (seed 0, 같은 정답 표면 매번 같은 폴드).
- 한 묶음씩 test로 두고 나머지로 학습해서 `<모델 이름>_1.pkl` ~ `_k.pkl`을 만듭니다.
- 결과: 폴드별 정확도, 전체 정확도(모든 녹화가 한 번씩 test), 상황별 정답률, 혼동 행렬, 틀린 트랙과 근거.

```
py tools\behavior\train_situation.py recordings\labels_1111.csv --cv 5 --out tools\behavior\models\situation_trees_1111.pkl
```

GUI에서는 설정의 **교차 검증**을 켜고 겹 수를 정한 뒤 학습 시작. 결과 탭에 모든 폴드의 test 트랙이 한 표로 나오고(구분 열 = 폴드, 보기에서 폴드별로 거를 수 있음), 상황별 정답률·혼동 행렬은 결정 트리 탭에 나옵니다. 표에서 줄을 더블클릭하면 그 녹화를 판정한 폴드의 모델로 뷰어가 열립니다.

### 뷰어에서 여러 파일 보기

- **파일 열기...**에서 .pcr(또는 트랙 CSV)을 여러 개 고르거나, **폴더 열기...**로 폴더의 .pcr을 전부 엽니다.
- 보고 있는 파일을 먼저 읽고, 나머지는 뒤에서 다음 파일부터 차례로 읽어 둡니다. 읽은 파일은 기억해 두어서 다시 넘어올 때 바로 나옵니다.
- **◀ ▶** 버튼이나 **PageUp / PageDown**으로 파일을 넘깁니다. '시나리오 결과' 탭에는 읽은 파일의 결과가 차례로 쌓입니다.
- 모델을 바꾸면 파일을 다시 읽지 않고 판정만 새로 합니다.

### 측정 영역 (Radar Studio의 Sensor Spec)

Radar Studio에서 정한 측정 설정(x·y 범위, 시야각, 방향)은 녹화 파일(.pcr) 헤더에 저장됩니다.

- **학습**: 기본으로 녹화 파일마다 이 영역을 읽어서, 영역(박스 + 시야각) 안의 프레임만 씁니다. 영역 밖에서만 잡힌 벽·물체 트랙은 자동으로 빠집니다. 학습 화면의 '측정 영역'에서 직접 값을 넣을 수도 있고, 명령줄은 `--region auto | none | xmin,xmax,ymin,ymax[,시야각[,방향]]`.
- **모델**: 학습에 쓴 영역이 모델에 같이 저장되고, 뷰어는 그 영역으로 판정합니다 (오른쪽 위 '판정 영역(모델)').
- **뷰어 표시**: '표시 영역'은 기본으로 녹화 파일 설정을 따르고(점선 박스와 시야각 선), 값을 고쳐 '적용'하면 화면만 바뀝니다. 판정 영역은 모델 기준이라 바뀌지 않습니다.

### 같은 사람 잇기와 특징 (모델 버전 3)

레이더는 멈춘 사람을 놓치기 때문에, 학습과 판정 모두 아래 규칙으로 트랙을 먼저 정리합니다 (`situation_core.stitch`).

- 측정 영역 **안**(외곽·문이 아닌 곳)에서 **거의 멈춘 채** 사라짐 → 그 자리에 멈춰 있는 사람으로 봄
- 측정 영역 안에서 갑자기 나타남 → 멈춰 있던 사람이 다시 움직인 것. 사라진 자리와 1m 안이면 **같은 사람으로 이어 붙이고**, 그 사이는 '안 보이는 정지'로 채움
- 외곽이 아닌 곳(문 앞 포함)에서 끊겼다가 5초 안에 1m 안에서 다시 잡힘 → 레이더가 다시 잡은 같은 사람
- 시간이 겹치는 두 트랙이 계속 0.6m 안에 붙어 다님 → 한 사람이 동시에 여러 ID로 잡힌 것이라 하나로 합침 (3개 이상도)
- 다시 나타나지 않으면 녹화 끝까지(최대 15분) 그 자리에 멈춰 있다고 봄
- **외곽으로 나간 뒤 30초 안에, 나간 자리 1.2m 안에서 다시 나타남** → 같은 사람이 다시 들어온 것 (반복 접근). 나가 있던 동안은 정지로 세지 않고 비워 둠. 같은 레이더 ID로 영역 밖에 나갔다 들어온 것도 다시 들어온 것으로 셈
- 외곽 = 측정 영역의 좌우 끝·먼 쪽 끝·시야각 끝에서 0.5m 안 (레이더 1m 안은 시야각이 좁아도 외곽 아님)
- **문으로 사라짐** = 레이더 1m 안에서 사라짐
- **문에서 나옴** = 레이더 1m 안에서 처음 잡힘, 또는 1.75m 안에서 처음 잡힌 뒤 0.6초 동안 레이더에서 곧장 멀어짐(0.25m 이상 움직였고 그중 80% 이상이 바깥 방향). 레이더는 사람이 문에서 나와 1~2걸음 걸은 뒤에야 트랙을 만들어서, 실제 외출 녹화는 대부분 1.1~1.7m에서 처음 잡힙니다. 그래서 거리만으로는 문에서 나온 사람과 옆으로 지나가다 잡힌 사람을 구분할 수 없고, 처음 움직이는 방향으로 구분합니다 (외출은 0.87~0.96, 통과·귀가는 대부분 음수). 기준이 60%였을 때는 1.33m에서 바깥으로 비스듬히(70%) 걸어간 통과(1-8)가 외출로 판정되어서 80%로 올렸습니다 (5겹 교차 검증: 외출로 잘못 판정 0개, 외출 10/11). 끄면(1m 안만) 외출 녹화 대부분이 '영역 안에서 나타남'이 되어 외출 2/11로 떨어집니다.
- 이어 붙인 사람은 `T2+0`처럼 레이더 ID를 이어서 표시하고, 레이더가 놓친 구간은 점이 흐리게 보입니다.

상황 트리 특징은 32개입니다. 상황 정의에 맞춰 추가한 것: 총 정지 시간(안 보이는 정지 포함), 문에서 떨어져 정지한 시간(엘리베이터 대기), 안 보이는 정지 시간, 문 가까이 있던 시간, 움직인 시간, 머문 범위, 처음 잡힌 곳·현재 위치에서 외곽까지 거리, 문으로 사라짐, 외곽으로 사라짐, 최근 60초 동안 (문이 아닌 곳에서) 나타난 횟수(반복 접근), 처음 잡힌 곳에서 옆으로 간 거리, 문 반대편으로 건너감(통과), 처음 잡힌 곳보다 멀어진 거리, 처음 잡힌 곳보다 문에 다가간 정도, 문에서 나옴(외출).

버전 3에서 고친 것: 트랙이 시작되고 속도를 아직 못 구하는 처음 1초를 '정지'로 세던 버그(지나가는 사람에게 정지 시간 1초 이상이 생겨서 외출로 판정되던 원인)를 고쳐서 이 구간은 '판단 전'으로 둡니다. 버전 2 모델은 열 때 다시 학습하라고 알려줍니다.

### 상황 정의 조건과 트리 3개 (모델 버전 3)

결정 트리가 정의와 안 맞는 상황을 고르지 않도록 정의 조건을 고정 규칙으로 둡니다 (`situation_core.RULES`).

| 상황 | 언제 | 조건 |
|---|---|---|
| 귀가, 방문 | 사라질 때 | 문으로 사라짐 (또는 녹화 끝까지 문 앞에 있음) |
| 배달 | 사라질 때 | 외곽으로 나감 (또는 녹화 끝날 때 외곽에 있음) |
| 외출 | 항상 | 문에서 나옴, 처음 잡힌 곳보다 0.5m 이상 문에 다가가지 않음 |
| 외출, 통과 | 사라질 때 | 문으로 사라지지 않음 |
| 반복 접근 | 항상 | 최근 60초 안에 2번 이상 나타남 |

- 판정할 때: 트리 확률이 가장 높은 상황이 조건을 어기면 다음으로 확률이 높은 상황을 고릅니다. 바뀐 경우 뷰어 근거와 학습 결과의 '근거' 열에 `트리는 배달 75%였지만 조건(...)에 안 맞아 방문`처럼 나옵니다.
- 학습할 때: 조건을 아직 못 채운 순간의 정답은 '판단 중'으로 바꿔서 학습합니다 (예: 반복 접근인데 아직 한 번만 나타남). 사라진 순간의 정답이 조건에 안 맞으면 그 샘플은 빼고 **확인 필요** 탭에 보여줍니다. 정답 표나 녹화를 확인해보세요.

트리는 3개입니다.
1. 움직임 트리 (프레임마다, 가짜 데이터로 학습)
2. 상황 트리 (0.5초마다, '판단 중' 포함): 진행 중 판정과 카메라 촬영에 씀. 기본 깊이 7
3. **최종 판정 트리** (사람이 사라지거나 녹화가 끝난 순간, '판단 중' 없음): 정답이 정해진 뒤의 스냅샷 + 사라진 순간(5배)으로 학습. 기본 깊이 5. 진행 중 판정과 최종 판정을 한 트리로 하면 사라진 순간 샘플이 너무 적어서 최종 판정이 흔들려서 따로 둡니다.

사라질 때 최종 판정이 이상 상황(60% 이상)이면 그때도 카메라를 찍습니다 (짧게 나타났다 사라지는 반복 접근).

labels_1111.csv로 해본 결과 (test 14트랙): 최종 판정 13/14, 파일 촬영 판단 13/13. 틀린 것은 2-10(귀가 → 방문). 문까지 곧장 와서 바로 사라진 방문(4-3, 4-6, 4-7)이 학습 데이터에 있어서, 기다리지 않은 방문과 귀가는 레이더로는 구분이 안 됩니다.

상황은 `방문`과 `배달`(= `배달/택배`, `택배`)로 나뉘었습니다. 예전 특징(16개)으로 학습한 모델은 열 때 다시 학습하라고 알려줍니다.
